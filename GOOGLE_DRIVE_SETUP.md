# Подключение Google Drive через сервисный аккаунт

Пошагово: как получить ключ сервисного аккаунта, создать общую папку и дать к ней доступ, подключить её к приложению и проверить, что всё работает. Все команды запускаются из `syllabus-ai-backend/`. Если стенд уже настроен на локальную копию Drive, переходите сразу к [чек-листу в конце](#чек-лист-для-текущего-стенда).

Что приложение делает с Drive:
- **читает** силлабусы прямо из папок школ в Drive, без импорта и без копий (каталог Drive, шаг 8);
- **копирует** каждую новую версию силлабуса в папку её школы (задача beat `sync_drive_files`, раз в минуту).

Всё это работает с одной **общей папкой**, внутри которой лежит по подпапке на каждую школу:

```
Syllabi                                  ← общая папка, её ID получает приложение
├── School of Digital Technologies       ← папка школы: сюда уходят новые версии её силлабусов
│   ├── Алгоритмизация и программирование.docx
│   └── …
├── School of Economics and Management
└── …
```

Названия подпапок должны совпадать с названиями школ в приложении (регистр и лишние пробелы не важны). Недостающие подпапки команда `drive-setup` создаст сама (шаг 7).

## Быстрый путь: всё через интерфейс

Войдите как **офис провоста** и откройте **Schools & Drive → Подключение Google Drive**. Там те же шаги, что ниже, без `.env` и терминала:

1. **Ключ сервисного аккаунта** — «Загрузить ключ (.json)». Ключ проверяется и сохраняется на сервере (`SECRETS_ROOT`, права 600), после этого приложение сразу переходит на Google Drive. На экране виден email аккаунта, с которым нужно поделиться папкой.
2. **Общая папка** — вставьте ссылку или ID, при необходимости укажите пользователя Workspace для делегирования и отметьте «Только чтение». Нажмите «Сохранить настройки».
3. **Проверка подключения** — проверяет ключ, общую папку и папки всех школ, а с галочкой ещё и запись. По каждому пункту показывается ✓, ⚠ или ✗ с причиной.
4. **Папки школ** — «Предпросмотр», затем «Связать папки школ» (то же, что `drive-setup`).
5. **Силлабусы в Google Drive** (видят и администраторы школ) — приложение читает силлабусы прямо из папок школ, см. шаг 8. Папка школы на семестр задаётся карандашом в таблице «School connections», затем «Обновить» или «Обновить всё из Drive».

Настройки из интерфейса важнее `DRIVE_*` и `GOOGLE_*` из `.env`. Если удалить ключ («Удалить ключ»), приложение снова будет работать по `.env`. Воркеры подхватывают изменения без перезапуска. Администраторы школ и КОК видят статус подключения, а менять его может только офис провоста.

Ниже то же самое пошагово, через `.env` и команды.

---

## 0. Решите, где будет лежать общая папка

У сервисного аккаунта **нет собственного места на диске**. Читать он может любую папку, которой с ним поделились, а **загружать файлы** — только в одно из двух мест:

| Вариант | Где общая папка | Что нужно | Загрузка |
|---|---|---|---|
| **A. Shared Drive** — рекомендуется | В общем диске | Добавить email сервисного аккаунта в участники общего диска | ✅ |
| **B. Диск почты школ** | В «Моём диске» общей почты, например `schools@narxoz.kz` | Админ Google Workspace включает domain-wide delegation | ✅ |
| **C. Только чтение** | Где угодно | Поделиться папкой с email аккаунта (Читатель) | ❌ только чтение силлабусов |

> ⚠️ Если поделиться с сервисным аккаунтом обычной папкой из чьего-то «Моего диска» (даже с правами «Редактор») без варианта B, чтение силлабусов и создание подпапок будут работать, а загрузка файлов упадёт с ошибкой `storageQuotaExceeded`. Команды `drive-check` и `drive-setup` предупреждают об этом заранее.

## 1. Включите Google Drive API

1. Откройте https://console.cloud.google.com и выберите проект, в котором создан сервисный аккаунт.
2. **APIs & Services → Library**, найдите **Google Drive API** и нажмите **Enable**.

Без этого любая операция завершится ошибкой «The Google Drive API is not enabled…».

## 2. Получите JSON-ключ сервисного аккаунта

Пропустите этот шаг, если ключ (`.json`) у вас уже есть.

1. **IAM & Admin → Service Accounts**, откройте нужный аккаунт.
2. Запишите его **email**, вида `syllabus-ai@<project>.iam.gserviceaccount.com`. Он понадобится на шаге 4.
3. **Keys → Add key → Create new key → JSON**. Браузер скачает файл.

> Если кнопка недоступна, создание ключей запрещено политикой организации (`iam.disableServiceAccountKeyCreation`). Попросите администратора Google Cloud.

Внутри ключа должно быть `"type": "service_account"`, а также поля `client_email`, `client_id` и `private_key`.

## 3. Положите ключ в `secrets/`

```bash
mv ~/Downloads/<project>-xxxxxxxx.json secrets/google-drive.json
chmod 600 secrets/google-drive.json
```

- Папка `secrets/` уже в `.gitignore` и `.dockerignore`: в git и в Docker-образ ключ не попадёт.
- `docker-compose.yml` монтирует `./secrets` во все контейнеры как `/secrets` (только чтение).
- Ключ — это пароль: не отправляйте его в чаты и не коммитьте. Если ключ утёк, удалите его в консоли (**Keys → Delete**) и создайте новый.

## 4. Создайте общую папку и дайте к ней доступ

**Вариант A — общая папка в Shared Drive**
1. В Google Drive: **Общие диски → Создать**, например «Syllabus AI» (или выберите существующий общий диск).
2. На общем диске: **Управление участниками** → email сервисного аккаунта → роль **Менеджер контента** (Content manager) → **Отправить**.
3. Внутри общего диска создайте папку `Syllabi`. Если силлабусы уже лежат в Drive, перенесите туда папки школ. Это и есть общая папка.

**Вариант B — общая папка в «Моём диске» почты школ** (domain-wide delegation делает админ Google Workspace)
1. Войдите в Drive под общей почтой школ и создайте там папку `Syllabi` (или используйте существующую с папками школ).
2. Админ открывает https://admin.google.com → **Безопасность → Доступ к данным и управление ими → Управление API → Делегирование доступа на уровне домена → Добавить**:
   - **Client ID** — число из поля `client_id` в JSON-ключе;
   - **OAuth scopes**, оба через запятую: `https://www.googleapis.com/auth/drive,https://www.googleapis.com/auth/drive.readonly` (при `DRIVE_READ_ONLY=true` приложение запрашивает второй scope, при `false` — первый).
3. На шаге 5 задайте `GOOGLE_IMPERSONATE_USER=<эта почта>`. Делиться папкой с сервисным аккаунтом не нужно: он работает от имени почты.

**Вариант C — общая папка только для чтения**
Откройте папку с силлабусами → **Поделиться** → email сервисного аккаунта → **Читатель** → **Отправить**. Доступ наследуется вложенными папками.

**ID общей папки** — последняя часть ссылки, когда папка открыта в браузере:
`https://drive.google.com/drive/folders/`**`1AbC…xyz`** (для папки в общем диске так же; ID самого общего диска не подходит, нужен ID папки внутри него).

## 5. Настройте `.env`

```env
DRIVE_PROVIDER=google
# В Docker путь начинается с /secrets; без Docker — ./secrets/google-drive.json
GOOGLE_CREDENTIALS_FILE=/secrets/google-drive.json
# Только для варианта B:
# GOOGLE_IMPERSONATE_USER=schools@narxoz.kz
# Сначала только чтение: приложение ничего не изменит в Drive
DRIVE_READ_ONLY=true
# Общая папка: сюда идут версии школ, для которых своя папка не задана
DRIVE_DEFAULT_FOLDER_ID=<ID общей папки>
```

Если раньше стенд работал на локальной копии, удалите строку `DRIVE_STUB_ROOT_IN_DOCKER=/drive-local`: при `DRIVE_PROVIDER=google` она не нужна.

Примените настройки (контейнеры пересоздадутся):

```bash
docker compose up -d
```

## 6. Проверьте доступ к общей папке

```bash
docker compose exec api python -m app.cli drive-check --folder <ID общей папки>
```

Пример вывода:

```
credentials   /secrets/google-drive.json (service_account)
account       syllabus-ai@narxoz-syllabus.iam.gserviceaccount.com  <- share the Drive folders with this email
project       narxoz-syllabus
acting as     the service account itself
access        read-only (DRIVE_READ_ONLY=true)

folder 1AbC…xyz
  name        Syllabi
  location    Shared Drive
  can upload  yes
  contents    3 items: School of Digital Technologies, School of Economics and Management, …
```

- `FAIL` — что-то не работает, текст подскажет причину (см. таблицу ниже). Команда завершается с кодом 1.
- `WARN uploads will fail` — папка лежит в чьём-то «Моём диске», а `GOOGLE_IMPERSONATE_USER` не задан: читать можно, загружать нельзя. Нужен вариант A или B.

## 7. Подключите общую папку к приложению

Одна команда настраивает то, что иначе пришлось бы вводить вручную на экране «Schools & Drive» для каждой школы:

```bash
# Сначала посмотреть, что будет сделано (ничего не меняет)
docker compose exec api python -m app.cli drive-setup <ID общей папки> --semester "Fall 2026" --dry-run
# Применить
docker compose exec api python -m app.cli drive-setup <ID общей папки> --semester "Fall 2026"
```

Что делает команда:
1. Проверяет ключ и доступ к общей папке (как `drive-check`) и останавливается, если доступа нет.
2. Для каждой школы из базы ищет в общей папке подпапку с её названием.
3. Недостающие подпапки **создаёт**. Не создаёт при `DRIVE_READ_ONLY=true` или с флагом `--no-create`: тогда такие школы помечаются как `missing`.
4. Записывает ID подпапки в папки загрузки школы на этот семестр («Schools & Drive»). Существующие записи обновляются, в том числе оставшиеся от импорта из локальной копии (ID вида `drive-download-…`, с настоящим Drive они не работают). Если записи нет, она создаётся.

Пример вывода:

```
School folders in 1AbC…xyz for Fall 2026:
  found         School of Digital Technologies  ->  1Def…
  created       School of Economics and Management  ->  1Ghi…

Schools & Drive: 1 folder(s) updated, 1 created.
```

**Если в Drive уже есть папка одной школы** (внутри неё сразу папки курсов, как в нынешней локальной копии `drive-download-…`), есть два пути:
- положить её внутрь общей папки и назвать так же, как школа в приложении (`School of Digital Technologies`), затем запустить `drive-setup`;
- или ничего не переносить, а указать ID этой папки для школы вручную на экране «Schools & Drive».

Команду можно запускать повторно, она ничего не дублирует. Для нового семестра запустите её с другим `--semester`. Если в общей папке появилась новая школа, просто запустите ещё раз. Папку отдельной школы можно поменять вручную на экране «Schools & Drive».

## 8. Силлабусы читаются прямо из Drive (каталог)

Импорта нет: приложение хранит только **каталог** — для каждого файла его ID, имя, папку дисциплины и номер версии в Drive — и результаты проверок. Сами файлы не копируются.

```
Осень 2026-2027 силлабусы/              ← папка школы на семестр (задаётся на Schools & Drive)
├── Алгоритмизация и программирование/   ← папка дисциплины
│   ├── Силлабус_RU.docx                 ← силлабус «Алгоритмизация и программирование · Силлабус_RU»
│   └── Syllabus_EN.docx
└── …
```

1. На **Schools & Drive** в таблице «School connections» карандашом задайте для школы и семестра ID её папки в Drive (администратор школы — для своей школы, офис проректора и КОК — для любой).
2. Нажмите **«Обновить»** в панели «Силлабусы в Google Drive». Чтение 89 папок и 575 файлов занимает около 10 секунд. Дальше beat перечитывает папки сам каждые `DRIVE_SYNC_INTERVAL_S` (по умолчанию 15 минут).
3. Силлабусы появляются в реестре **Syllabi** со ссылкой «Открыть в Google Drive». Проверку запускают офис проректора, КОК и администраторы школы (кнопка «Run AI Check» / «Проверить снова») или сессия.

Как это работает:
- **Проверка** скачивает текущий файл из Drive во временную папку, анализирует и сразу удаляет. Если файл изменили в Drive после последнего чтения, проверка сама переходит на новую версию.
- **Изменённый файл** (новая версия в Drive) становится новой версией силлабуса: он возвращается в Draft, а в реестре появляется пометка «Изменён в Drive». Прежние результаты остаются в истории версий.
- **Удалённый из Drive файл** скрывается из реестра и сессий (фильтр `include_missing` показывает его вместе с результатами).
- Пропускаются файлы вне папок дисциплин и не-силлабусы (не .docx, .pdf или Google Doc). Список с причинами — в подсказке «Пропущено».
- У курсов из Drive нет ведущего преподавателя. Шаг согласования «Отправить руководителю программы» выполняет администратор школы или офис проректора, а уведомления ведущему получают администраторы школы.
- Кнопка «Скачать» у версии из Drive отдаёт файл прямо из Drive.

Новая база с нуля: `python -m app.cli setup-schools` (4 школы и рубрика), `python -m app.cli add-test-users` (пользователи всех ролей), затем шаги 1–2.

## 9. Включите загрузку в Drive

1. В `.env`: `DRIVE_READ_ONLY=false`, затем `docker compose up -d`.
2. Проверьте запись (команда загрузит и сразу удалит тестовый файл) и создайте папки школ, которые на шаге 7 остались `missing`:
   ```bash
   docker compose exec api python -m app.cli drive-check --folder <ID общей папки> --write
   docker compose exec api python -m app.cli drive-setup <ID общей папки> --semester "Fall 2026"
   ```

Новые версии уходят в Drive раз в минуту. Версии, загруженные раньше (в том числе при `DRIVE_READ_ONLY=true`), тоже отправятся автоматически. Если отправка не удалась, причина видна в поле `drive_error` версии, а попытка повторится.

## Частые ошибки

| Сообщение | Причина | Что сделать |
|---|---|---|
| `GOOGLE_CREDENTIALS_FILE … does not exist` | Неверный путь | В Docker путь `/secrets/<файл>`, без Docker — `./secrets/<файл>` |
| `DRIVE_PROVIDER=google needs GOOGLE_CREDENTIALS_FILE` | Не задан путь к ключу, приложение не стартует | Добавьте переменную в `.env` |
| `The Google Drive API is not enabled …` | API выключен в проекте аккаунта | Шаг 1 |
| `Drive folder not found: share it with the service account's email …` | С аккаунтом не поделились папкой или ID неверный | Шаг 4, проверьте ID по ссылке |
| `The service account has no Drive storage of its own …` (`storageQuotaExceeded`) | Загрузка в «Мой диск» без делегирования | Вариант A или B |
| `No permission to add files to this Drive folder …` | У аккаунта роль «Читатель» | Дайте «Редактор» или «Менеджер контента» |
| `Google refused the credentials …` / `unauthorized_client` | Делегирование не настроено или scopes не совпадают | Вариант B, шаг 2: оба scope, Client ID из ключа |
| `GOOGLE_IMPERSONATE_USER only works with a service account key` | Задан `GOOGLE_IMPERSONATE_USER`, но файл — OAuth-ключ пользователя | Уберите `GOOGLE_IMPERSONATE_USER` или используйте ключ сервисного аккаунта |
| `drive-setup`: школа `missing` | Подпапки нет, а создание выключено (`DRIVE_READ_ONLY=true` или `--no-create`) | Создайте подпапку вручную или запустите после шага 9 |
| `drive-setup`: создана лишняя папка вместо существующей | Название подпапки не совпадает с названием школы в приложении | Переименуйте подпапку в Drive, удалите лишнюю и запустите снова |

## Безопасность

- Одному приложению — один ключ. Ротация: создайте новый ключ, замените файл, выполните `docker compose up -d`, затем удалите старый ключ в консоли.
- Давайте минимальный доступ: для чтения силлабусов хватает «Читателя», «Менеджер контента» нужен только там, куда идёт загрузка.
- При `ENV=prod` приложение не запустится с `DRIVE_PROVIDER=stub`, поэтому файлы гарантированно уходят в Drive.
